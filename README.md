# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Vite

Структура проекта:
- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом

Важные файлы:
- index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/main.ts — точка входа приложения
- src/scss/styles.scss — корневой файл стилей
- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами

# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах эндпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на эндпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
В приложении используются две сущности, которые описывают данные, — товар и покупатель. Для описания структуры их данных применяются интерфейсы IProduct и IBuyer.

#### Интерфейс товара IProduct
Интерфейс описывает товар, отображаемый в каталоге.

interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}

Описание полей:
`id: string` — уникальный идентификатор товара.
`description: string` — описание товара.
`image: string` — ссылка на изображение товара.
`title: string` — название товара.
`category: string` — категория товара.
`price: number | null` — цена товара. Если цена отсутствует, значение равно `null`, и товар будет недоступен для покупки.

#### Интерфейс покупателя IBuyer
Интерфейс описывает данные, указанные покупателем при оформлеении заказа.

interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}

Описание полей:
`payment: TPayment` — выбранный способ оплаты: банковской картой (card) или при получении (cash). Тип `TPayment` определяет способ оплаты: `type TPayment = 'card' | 'cash'`.
`email: string` — адрес электронной почты покупателя.
`phone: string` — номер телефона покупателя.
`address: string` — адрес доставки заказа.

### Данные для работы с сервером
В приложении применяются интерфейсы, необходимые для взаимодействия с сервером, получения объектов, передачи их на сервер.

#### Интерфейс ответа сервера IProductListResponse
Интерфейс описывает объект, который сервер возвращает при запросе списка товаров.

interface IProductListResponse {
  total: number;
  items: IProduct[];
}

Описание полей:
`total: number` — общее количество товаров.
`items: IProduct[]` — массив товаров, каждый элемент которого соответствует интерфейсу IProduct.

#### Интерфейс запроса заказа IOrderRequest
Интерфейс описывает данные заказа, которые приложение отправляет на сервер.

interface IOrderRequest extends IBuyer {
  total: number;
  items: string[];
}

Описание полей:
`IBuyer` — содержит данные покупателя: способ оплаты, email, телефон и адрес.
`total: number` — общая стоимость заказа.
`items: string[]` — массив идентификаторов товаров в заказе.

#### Интерфейс ответа сервера IOrderResponse
Интерфейс описывает объект, который сервер возвращает после оформления заказа.

interface IOrderResponse {
    id: string;
    total: number;
}

Описание полей:
`id: string` — идентификатор оформленного заказа.
`total: number` — итоговая стоимость заказа, подтверждённая сервером.

### Модели данных
В проекте присутствуют три класса, отвечающие за хранение и обработку данных: каталог товаров, корзина и данные покупателя.
#### Модель каталога товаров ProductCatalogModel
Данная модель хранит список всех товаров, а также товар, выбранный для подробного отображения.

Описание полей:
`products: IProduct[]` - массив всех товаров каталога.
`preview: IProduct | null` - товар, выбранный для подробного отображения. Когда товар не выбран - `null`.

Конструктор:
`constructor()` - создаёт модель с пустым массивом товаров, а также без выбранного товара для подбного отображения. Не принимает параметры.

Методы:
`setProducts(products: IProduct[]): void` — сохраняет массив товаров, полученный в параметрах метода.
`getProducts(): IProduct[]` — получение массива товаров из модели.
`getProductById(id: string): IProduct | undefined` — возвращает товар с указанным id. Если товар не найден, то возвращает undefined.
`setPreview(product: IProduct): void` — сохраняет товар, который выбран для подробного отображения.
`getPreview(): IProduct | null` — получение товара выбранного для подробного отображения, или null, если товар не выбран.

#### Модель корзины CartModel
Модель хранит товары, которые покупатель выбрал для покупки. Предоставляет методы для управления корзиной и расчёта стоимости её содержимого.

Описание полей:
`items: IProduct[]` — массив товаров, добавленных в корзину.

Конструктор:
`constructor()` — создаёт пустую корзину. Не принимает параметры.

Методы:
`getItems(): IProduct[]` — возвращает массив товаров в корзине.
`addProduct(product: IProduct): void` — добавляет товар, полученный в параметре, в корзину.
`removeProduct(product: IProduct): void` — удаляет товар из корзины.
`clear(): void` — удаляет все товары из корзины.
`getTotal(): number` — возвращает стоимость всех товаров в корзине.
`getCount(): number` — возвращает количество товаров в корзине.
`hasProduct(id: string): boolean` — проверяет, есть ли в корзине товар с указанным id. Возвращает true, если товар найден, и false, если не найден.

#### Модель покупателя BuyerModel
Модель хранит данные покупателя, необходимые для оформления заказа. Позволяет обновлять отдельные поля, проверяет заполненность данных и очищает их после оформления заказа.

Описание полей:
`payment: TPayment | null` — вид оплаты, который выбрали. Значение `null` означает, что вид оплаты ещё не выбран.
`address: string` — адрес доставки. Изначально пустая строка.
`phone: string` — телефонный номер покупателя. Изначально пустая строка.
`email: string` — адрес электронной почты покупателя. Изначально пустая строка.

Конструктор:
`constructor()` — создаёт модель с незаполненными данными покупателя. Не принимает параметры.

Методы:
`setBuyer(data: Partial<IBuyer>): void` — сохраняет переданные данные покупателя. Позволяет обновить одно или несколько полей, не удаляя значения остальных полей.
`getBuyer(): { payment: TPayment | null; address: string; email: string; phone: string }` — возвращает все данные покупателя.
`clear(): void` — очищает данные покупателя.
`validate(): Partial<Record<keyof IBuyer, string>>` — валидация заполненных данных покупателя. Возвращает объект с сообщениями об ошибках для незаполненных полей.

При проверке данных каждое поле считается валидным, если оно не пустое. Например, если способ оплаты не выбран, а электронная почта не указана, метод `validate()` может вернуть объект:
{
  payment: 'Не выбран вид оплаты',
  email: 'Укажите email',
}
Если ошибок нет, метод возвращает пустой объект.

### Слой коммуникации LarekApi
Класс слоя коммуникации отвечает за получение данных с сервера и отправку данных на сервер. Класс использует композицию, принимая в конструктор объект, соответствующий интерфейсу `IApi`, и вызывая его методы `get` и `post` для выполнения запросов к серверу.

Конструктор:
`constructor(api: IApi)` — принимает экземпляр API для выполнения HTTP-запросов.

Методы:
`getProductList(): Promise<IProductListResponse>` — выполняет GET-запрос для получения списка товаров с сервера.

`order(order: IOrderRequest): Promise<IOrderResponse>` — выполняет POST-запрос для отправки данных заказа на сервер и получения подтверждения оформления заказа.
